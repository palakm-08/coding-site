Understanding if __name__ == '__main__' in Python

Beginner Python

This is one of the most confusing Python lines for beginners — but don't worry, we'll break it down with real examples and make it crystal clear!

What does if __name__ == "__main__" mean?

Imagine you're writing a Python file — maybe a fun game or a simple calculator. Now ask yourself: should this file run some code only when it's opened directly? Or stay quiet if someone else imports it into their own project?

That's exactly what this line does. It's Python's way of saying: "Run this part only when the file is executed directly — not when it's imported."

It checks a built-in variable called __name__. If you run the file directly with python filename.py, then __name__ becomes "__main__". When the file is imported instead, __name__ is set to the module's name — not "__main__" — which is exactly what makes this check work.

So why should you care?

This small line is super useful when:

  • You're writing utility functions that others might import.
  • You want to test your code with print statements or small examples.
  • You're building Python scripts and want better control of when things happen.

What Is __name__ in Python?

__name__ isn't something you create — it's a special built-in variable that Python automatically sets for every file (module) as soon as it runs. Its value depends entirely on how the file was started:

  • Run directly (python greet.py): __name__ is set to "__main__".
  • Imported by another file (import greet): __name__ is set to the module's name — in this case, "greet".

You can see this yourself with one line:

Python — greet.py 
print(__name__)

Run this file directly, and it prints __main__. Import it from another file instead, and it prints greet. Same line of code, two different outputs — because __name__ changes depending on how Python started running the file.

"__main__" vs the module's name: "__main__" is just a fixed label Python uses for whichever file you told it to run directly. It's not related to a function called main() — Python doesn't require one. The module's own name (its filename, minus .py) is only used when that file is imported.

Why Do We Use if __name__ == "__main__"?

The short answer: it lets one Python file work two ways — as a script you run directly, and as a module other files can safely import.

  • Separates reusable code from "run this now" code. Functions and classes at the top of a file are meant to be reused. The if __name__ == "__main__": block is where you put the code that should only run when this specific file is the one being executed.
  • Stops the main logic from firing on import. Without the guard, anything you write at the top level — including function calls — runs the instant the file is imported, whether you wanted that or not.
  • Makes the file dual-purpose. Someone can run python greet.py to use it standalone, or import greet to reuse just the functions inside it — same file, two valid uses.

Let's See It in Action

Here's a simple example — run this file directly and it prints a greeting:

Python — greet.py 
def say_hello():
    print("Hello, world!")

if __name__ == "__main__":
    say_hello()

If you run greet.py directly, it prints Hello, world!. But if you import it from another file:

Python — app.py 
import greet

The say_hello() function is now defined and ready to use inside app.py, but it doesn't run automatically — the code inside the if __name__ == "__main__" block does not execute, because __name__ is "greet" here, not "__main__". This keeps your code clean and prevents unwanted side effects when using modules.

Quick summary: __name__ == "__main__" is True only when you run the file directly. It's False when the file is imported by another script.

Without vs With the Guard

The difference is easiest to see side by side. Same function, same import — one version behaves badly, the other doesn't.

Without the guard

Python — greet.py (no guard) 
def say_hello():
    print("Hello, world!")

say_hello()

Now import it from app.py:

Python — app.py 
import greet
# Output: Hello, world!  ← ran immediately, even though you never called it

Just importing greet triggers Hello, world! — you didn't ask for that. If say_hello() did something bigger, like sending an email or writing to a file, that would fire too, purely from an import.

With the guard

Python — greet.py (guarded) 
def say_hello():
    print("Hello, world!")

if __name__ == "__main__":
    say_hello()
Python — app.py 
import greet
# No output — say_hello() is only defined, not called

Now importing greet just makes say_hello() available to use — it doesn't run on its own. app.py can call greet.say_hello() whenever it actually wants to.

Python Module vs Python Script

These two words describe the same kind of file — a .py file — just used in different ways:

  • Module — a Python file meant to be imported and reused by other files. Its functions and classes are the point; it usually isn't run on its own.
  • Script — a Python file meant to be run directly, top to bottom, to do something.

Here's the thing: the exact same file can be both, depending on how it's used. A tiny project makes this clearer:

project/
├── calculator.py
└── app.py
Python — calculator.py 
def add(a, b):
    return a + b

if __name__ == "__main__":
    print(add(2, 3))

1. Executed directly — running python calculator.py sets __name__ to "__main__", so the guarded block runs and prints 5. Here, calculator.py is acting as a script.

Python — app.py 
import calculator

print(calculator.add(10, 20))   # 30

2. Imported into app.py — now __name__ inside calculator.py is "calculator", not "__main__", so the guarded print(add(2, 3)) stays silent. Only the add() function is used, from app.py. Here, calculator.py is acting as a module.

Same file, two roles — and __name__ is exactly what tells Python which one applies each time.

What Happens When You Import a Python File?

A common misconception is that importing a file "does nothing" until you call something from it. That's not quite right — importing a module runs its top-level code immediately. What it doesn't run is anything guarded behind if __name__ == "__main__":, because that condition is false during an import.

Python — settings.py 
print("Loading settings...")   # top-level — runs on import

VERSION = "1.0"

def show_version():
    print(f"Version: {VERSION}")

if __name__ == "__main__":
    show_version()   # only runs if settings.py is run directly

Importing this file with import settings immediately prints Loading settings... and defines VERSION and show_version() — that's real code executing. What it skips is the guarded show_version() call at the bottom, because __name__ is "settings", not "__main__", at that moment.

Correction to a common myth: Importing a module isn't a no-op. Python runs every top-level statement in the file — print statements, variable assignments, even function calls — as soon as it's imported. The only thing skipped is code inside if __name__ == "__main__":, because that check simply evaluates to False on import.

Common Mistakes

  • Using = instead of ==: if __name__ = "__main__" is a syntax error. Always use == for comparison.
  • Indentation errors: The code inside the if block must be properly indented — 4 spaces in.
  • Expecting it to run on import: Code inside this block won't run when the file is imported. That's the whole point!
  • Forgetting the underscores: It must be __name__ and "__main__" — double underscores on both sides.
  • Assuming imports don't execute anything: Top-level code in an imported file still runs. Only the guarded block is skipped.

Wrap Up

So now you know what if __name__ == "__main__" means! It's not as scary as it looked. Think of it as a way to tell Python: "Only run this part when I'm executing the file directly."

This little line becomes really powerful when your projects grow or when you're sharing code with others. Keep practicing, and you'll start using it without even thinking about it!

FAQs

What does if __name__ == "__main__" mean in Python?

It's a check that's only True when the file is run directly, not when it's imported by another file. Code inside that block only runs during direct execution.

Why do we use if __name__ == "__main__"?

It lets a Python file work both as a standalone script and as an importable module, without its "run this now" code firing every time someone imports it.

What is __name__ in Python?

A built-in variable Python sets automatically on every file. It equals "__main__" when the file is run directly, or the module's name when it's imported.

What is __main__ in Python?

"__main__" is the fixed name Python gives to whichever file you executed directly. It's not a required function — Python doesn't need a main() function to run a file.

What happens when a Python file is imported?

Its top-level code runs immediately — assignments, function definitions, print statements included. The only thing skipped is code inside if __name__ == "__main__":.

Can I run a Python file without if __name__ == "__main__"?

Yes — the file will still run fine on its own. The guard only matters if you also plan to import that file elsewhere and don't want its top-level calls to run automatically.

What is the difference between a Python module and a script?

A module is a file meant to be imported and reused. A script is a file meant to be run directly. The same .py file can serve as either, depending on how it's used.

Why doesn't code inside if __name__ == "__main__" run when imported?

Because __name__ is set to the module's name during an import, not "__main__" — so the condition evaluates to False and the block is skipped.
