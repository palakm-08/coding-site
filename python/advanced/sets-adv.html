Python Set Comprehensions Explained

Set comprehensions build a set from an expression in one line. Same idea as list comprehensions, just with curly braces instead of square brackets — and duplicates get dropped automatically since the result is a set. Here's the example straight from the docs:

PythonPython docs example
# From the Python docs §5.4
a = {x for x in 'abracadabra' if x not in 'abc'}
a
# {'r', 'd'}
From the Python docs

Similarly to list comprehensions, set comprehensions are also supported: {x for x in 'abracadabra' if x not in 'abc'} gives {'r', 'd'}.

Kiddo extras — more set comprehension patterns

PythonKiddo example
# Syntax: {expression for item in iterable if condition}

# 1 — Unique squares (duplicates in input get merged)
nums = [1, 2, 2, 3, 3, 3, 4]
squares = {n**2 for n in nums}
print(squares)   # {1, 4, 9, 16}

# 2 — Unique first letters from a hero name list
heroes = ["Miles", "Mayday", "Ben", "Gwen", "Cindy"]
first_letters = {name[0] for name in heroes}
print(first_letters)   # {'M', 'B', 'G', 'C'}

# 3 — Even numbers only
evens = {n for n in range(1, 11) if n % 2 == 0}
print(evens)   # {2, 4, 6, 8, 10}

# 4 — Unique domain names from an email list
emails = ["user@gmail.com", "admin@yahoo.com", "peter@gmail.com", "test@gmail.com"]
domains = {email.split('@')[1] for email in emails}
print(domains)   # {'gmail.com', 'yahoo.com'}
Comprehension vs constructor: {x for x in items} is a set comprehension. set(items) creates a set directly. For simple deduplication, set(items) is cleaner. Use comprehensions when you need to transform or filter while building the set.

Python frozenset Explained

A frozenset is a set that can't be changed after it's created — no add(), no remove(), nothing. Same set behaviour (unordered, no duplicates, supports &, |, -), just locked.

PythonKiddo example
colors = frozenset({"red", "green", "blue"})
print(colors)

On its own that doesn't look very useful — why not just use a regular set? The answer is that being locked also makes a frozenset hashable, which opens up two things a regular set can't do: it can be a dictionary key, and it can sit inside another set.

Python Docs Tip: Use a normal set when data changes. Use a frozenset when the collection should never change.

Kiddo extra — using frozenset as a dictionary key

PythonKiddo example
# A regular set can't be a dictionary key
team = {"Peter", "Miles", "Gwen"}
# scores = {team: 95}   ← TypeError: unhashable type: 'set'

# A frozenset works fine as a key
team = frozenset({"Peter", "Miles", "Gwen"})
scores = {team: 95}
print(scores[team])   # 95

Kiddo extra — frozenset as an element inside another set

This one comes up more often than people expect — say you're storing a bunch of permission groups, and you want to know which combinations of permissions are actually in use, with duplicates removed:

PythonKiddo example
# Each user's permission set, as plain sets
user_permissions = [
    {"read", "write"},
    {"read"},
    {"write", "read"},  # same combo as the first one, different order
]

# set(user_permissions) would fail — plain sets can't go inside a set
unique_combos = {frozenset(p) for p in user_permissions}
print(len(unique_combos))   # 2 — {read, write} and {read} are the only distinct combos

Python Set Time Complexity

Sets are built on a hash table under the hood, which is why they stay fast even as the data grows. Here's roughly what each operation costs:

Operation Average Complexity
x in s O(1)
s.add(x) O(1)
s.remove(x) O(1)
s ^ t O(n + m)
s | t O(n + m)
s & t O(min(n,m))
s - t O(n)

This is why sets show up so often for lookups, filtering, dedup, and recommendation-style code — the moment you're checking membership repeatedly, a set beats a list by a wide margin as the data grows.

Common Mistakes With Comprehensions and frozenset

Confusing a set comprehension with a dict comprehension

{x for x in items} is a set comprehension. {x: y for x, y in pairs} — with a colon — is a dict comprehension. Mixing up the syntax is an easy typo that changes the return type entirely.

Trying to mutate a frozenset

my_frozenset.add(x) throws AttributeError: 'frozenset' object has no attribute 'add'. There's no add(), remove(), or update() on a frozenset — if you need to change it, build a new one instead.

Forgetting to convert before using a set as a key

{my_set: value} throws TypeError: unhashable type: 'set'. Wrap it first: {frozenset(my_set): value}.

Assuming O(1) lookup applies to lists too

x in my_list is O(n) — Python checks every element. Sets, frozensets, and dictionaries provide O(1) average-case membership or key lookup.

Advanced Python Set Interview Questions and Answers

These lean more technical than Part 1's — comprehensions, frozenset, and the complexity behind set operations tend to show up in intermediate rounds:

Q1 What is a set comprehension, and how is it different from a list comprehension?
A set comprehension uses curly braces — {expr for item in iterable} — and produces a set, so duplicates are removed automatically and the result is unordered. A list comprehension uses square brackets, keeps duplicates, and preserves order.
Q2 What is a frozenset and why would you use one?
An immutable set — no add(), remove(), or update() after creation. You'd reach for one when a collection needs to stay fixed, or when you need set behaviour somewhere that requires hashability, like a dictionary key.
Q3 Why can't a regular set be used as a dictionary key, but a frozenset can?
Dictionary keys have to be hashable, and hashability requires the value to never change. A regular set is mutable, so it's excluded — TypeError: unhashable type: 'set'. A frozenset can't change after creation, so it qualifies.
Q4 What is the time complexity of membership testing in a set versus a list?
Membership testing (x in collection) is O(1) on average for a set, because of its underlying hash table. On a list, it's O(n), because Python has to scan elements one at a time until it finds a match or reaches the end.
Q5 What is the time complexity of union and intersection?
Union (s | t) is roughly O(n + m), where n and m are the sizes of the two sets, since every element from both sets has to be visited. Intersection (s & t) is roughly O(min(n, m)), because Python iterates the smaller set and checks membership in the larger one.
Q6 Can you write a set comprehension to get all unique word lengths from a list of words?
{len(w) for w in words} — this iterates every word, takes its length, and collects the unique lengths into a set. For example, ["cat", "dog", "elephant"] would give {3, 8}.

The idea: register different Spider-Team lineups across seasons of the Spider-Verse, and store each lineup as a frozenset so it can be compared and looked up like a fixed combination. It's the same pattern you'd use for something a lot less fun in a real app — role combinations, tag sets, permission groups — anywhere you need to treat "this exact combination of things" as a single, lookup-able value.

Freeze each lineup

Store each season's Spider-Team as a frozenset of hero names. Because a frozenset is immutable, it's safe to use as a dictionary key or to compare directly against another lineup.

Build a season registry

Use a dictionary with frozenset keys — {frozenset(lineup): season_name} — so you can instantly look up which season a given team combination belongs to. Swap "season" for "role" or "permission group" and you've got the same pattern used for access-control lookups.

Detect duplicate lineups with a set comprehension

Use {frozenset(team) for team in all_teams} to collapse the list of lineups down to only the unique team combinations, even if two seasons reused the exact same roster.

Compare two seasons' rosters

Use intersection (&) on two frozensets to find heroes who appeared in both seasons, and difference (-) to find who was season-exclusive.
