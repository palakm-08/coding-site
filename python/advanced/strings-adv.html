Splitting Strings — split(), rsplit(), splitlines()

Three methods for breaking one string into several. split() and rsplit() cut on a separator; splitlines() cuts on line boundaries, which is a different job than it might look at first.

PythonPython docs examples
# split() with a separator — consecutive delimiters are NOT grouped
'1,2,3'.split(',')              # ['1', '2', '3']
'1,2,3'.split(',', maxsplit=1) # ['1', '2,3']
'1,2,,3,'.split(',')            # ['1', '2', '', '3', '']

# split() with no separator — runs of whitespace collapse, no empty strings at the edges
'1 2 3'.split()                # ['1', '2', '3']
'   1   2   3   '.split()      # ['1', '2', '3']

# rsplit() — identical to split() unless maxsplit limits it, then it cuts from the right
'1,2,3'.rsplit(',', maxsplit=1) # ['1,2', '3']  ← compare to split() above
From the Python docs: if sep isn't given, a different algorithm kicks in — runs of consecutive whitespace count as one separator, and leading/trailing whitespace never produces empty strings in the result. That's why ' 1 2 3 '.split() gives a clean ['1', '2', '3'] instead of a list full of empty strings.

Kiddo extra — splitlines() vs split('\n')

PythonPython docs example
text = 'ab c\n\nde fg\rkl\r\n'

text.splitlines()
# ['ab c', '', 'de fg', 'kl']

text.splitlines(keepends=True)
# ['ab c\n', '\n', 'de fg\r', 'kl\r\n']

# A trailing newline does NOT create an extra empty line with splitlines()...
"One line\n".splitlines()
# ['One line']

# ...but split('\n') gives you that trailing empty string
'Two lines\n'.split('\n')
# ['Two lines', '']
splitlines() isn't just split('\n') — from the Python docs: it also breaks on \r, \r\n, and several less common Unicode line boundaries, and it never leaves a stray empty string at the end for a trailing newline. If you're processing text that might come from different operating systems, splitlines() is the safer choice.
MethodWhat it does
s.split(sep=None, maxsplit=-1)Splits on sep (or any whitespace run if omitted), left to right
s.rsplit(sep=None, maxsplit=-1)Same as split(), but maxsplit counts from the right
s.splitlines(keepends=False)Splits on line boundaries; set keepends=True to keep the line-break characters

Splitting Around a Separator — partition(), rpartition()

partition() is a more targeted cousin of split() — instead of a list of every piece, it gives you exactly three things: what's before the separator, the separator itself, and what's after. Handy when you only care about the first (or last) split point.

PythonPython docs examples
'Monty Python'.partition(' ')
# ('Monty', ' ', 'Python')

"Monty Python's Flying Circus".partition(' ')
# ('Monty', ' ', "Python's Flying Circus")

# Separator not found — original string, then two empty strings
'Monty Python'.partition('-')
# ('Monty Python', '', '')

# rpartition() — same idea, but splits at the LAST occurrence
"Monty Python's Flying Circus".rpartition(' ')
# ("Monty Python's Flying", ' ', 'Circus')

# Separator not found — two empty strings, then the original string
'Monty Python'.rpartition('-')
# ('', '', 'Monty Python')

Kiddo extra — pulling apart a "key: value" line

PythonKiddo example
header = "Content-Type: text/html"

key, _, value = header.partition(": ")
print(key)     # Content-Type
print(value)   # text/html
# The middle value (the separator) is thrown away with _ since we don't need it
partition() vs split(sep, 1): both split at the first occurrence, but partition() always returns exactly 3 items — even when the separator isn't found — while split(sep, 1) returns a list that could have 1 or 2 items. partition() is usually the safer pick when you're about to unpack the result into named variables, like the example above.

Joining Strings — join()

join() flips the usual order around: instead of calling it on the pieces, you call it on the separator, and pass the pieces in. It's the most efficient way to glue a list of strings together in Python.

PythonPython docs examples
', '.join(['spam', 'spam', 'spam'])
# 'spam, spam, spam'

# A string is iterable too — join() will run over its characters
'-'.join('Python')
# 'P-y-t-h-o-n'

Kiddo extra — join() only accepts strings

PythonKiddo example
scores = [3, 1, 0]

# ", ".join(scores)   ← TypeError: sequence item 0: expected str instance, int found

# Convert every item to a string first
line = ", ".join(str(n) for n in scores)
print(line)   # 3, 1, 0
MethodWhat it does
sep.join(iterable)Joins the strings in iterable, placing sep between each pair — every item must already be a string

Replacing & Removing Text — replace(), removeprefix(), removesuffix()

Three ways to cut exact text out of a string, as opposed to strip() from Part 1, which removes a set of characters rather than an exact match.

PythonPython docs examples
# replace() — swaps every match unless count limits it
'spam, spam, spam'.replace('spam', 'eggs')
# 'eggs, eggs, eggs'
'spam, spam, spam'.replace('spam', 'eggs', 1)
# 'eggs, spam, spam'

# removeprefix() — removes ONE exact prefix, only if it's actually there
'TestHook'.removeprefix('Test')
# 'Hook'
'BaseTestCase'.removeprefix('Test')
# 'BaseTestCase'  ← unchanged, prefix doesn't match here

# removesuffix() — same idea, from the end
'MiscTests'.removesuffix('Tests')
# 'Misc'
'TmpDirMixin'.removesuffix('Tests')
# 'TmpDirMixin'  ← unchanged
removesuffix() vs strip() — from the Python docs: 'Monty Python'.rstrip(' Python') gives 'M', because rstrip() treats ' Python' as a bag of characters and keeps chewing through M-o-n-t-y too. 'Monty Python'.removesuffix(' Python') correctly gives 'Monty', because it only removes that exact substring if it's at the end. If you know the precise text you want gone, removeprefix()/removesuffix() is almost always what you actually meant.
MethodWhat it doesIf no match
s.replace(old, new, count=-1)Replaces occurrences of old with new (all, unless count limits it)Returns s unchanged
s.removeprefix(prefix)Removes prefix from the start, only if presentReturns s unchanged
s.removesuffix(suffix)Removes suffix from the end, only if presentReturns s unchanged

Aligning & Padding Strings — center(), ljust(), rjust(), zfill()

Four methods for padding a string out to a fixed width — useful for lining up columns of text output, or formatting IDs with leading zeros. All of them leave the string untouched if it's already at or past the target width.

PythonPython docs examples
# center() — pads both sides
'Python'.center(10)          # '  Python  '
'Python'.center(10, '-')     # '--Python--'
'Python'.center(4)           # 'Python'  ← width already smaller, unchanged

# ljust() — pads on the right, text stays left-aligned
'Python'.ljust(10)           # 'Python    '
'Python'.ljust(10, '.')      # 'Python....'

# rjust() — pads on the left, text stays right-aligned
'Python'.rjust(10)           # '    Python'
'Python'.rjust(10, '.')      # '....Python'

# zfill() — pads with '0' on the left, and is sign-aware
"42".zfill(5)              # '00042'
"-42".zfill(5)             # '-0042'  ← the sign stays in front, zeros go after it

Kiddo extra — a simple two-column scoreboard

PythonKiddo example
rows = [("Mbappe", 2), ("Haaland", 14)]

for name, goals in rows:
    print(name.ljust(10), str(goals).rjust(3))
# Mbappe       2
# Haaland     14
MethodWhat it does
s.center(width, fillchar=' ')Centers s, padding both sides equally
s.ljust(width, fillchar=' ')Pads on the right — s stays left-aligned
s.rjust(width, fillchar=' ')Pads on the left — s stays right-aligned
s.zfill(width)Pads with '0' on the left; a leading +/- sign stays in front

encode(), translate() & maketrans()

Three less-common methods that come up when you need to go beyond plain text — turning a string into bytes, or swapping a whole set of characters for others in a single pass.

encode() — turning a string into bytes

PythonPython docs example
encoded = 'Python'.encode()   # defaults to UTF-8
print(type(encoded))          # <class 'bytes'>
print(encoded)                # b'Python'
A str in Python is text; bytes is raw data. You'll reach for encode() when you need to send text over a network, write it to a binary file, or hash it — anywhere the receiving end expects bytes, not a Python string.

maketrans() + translate() — swap many characters in one pass

These two are meant to be used together. maketrans() builds a lookup table; translate() applies it. It's the right tool when replace() would mean calling it several times in a row.

PythonKiddo example
# Two equal-length strings — each character in the first maps to the one in the same spot in the second
table = str.maketrans("abc", "xyz")
"abcdef".translate(table)
# 'xyzdef'

# A third argument lists characters to delete entirely
strip_table = str.maketrans("", "", "aeiou")
"Mbappe scores again".translate(strip_table)
# 'Mbpp scrs gn'  ← every vowel removed in one pass
From the Python docs: maketrans() can also take a single dict argument, mapping Unicode ordinals or single characters to a replacement (or to None to delete them). The two-or-three-string form shown above is just the more common shortcut for simple substitutions.
MethodWhat it does
s.encode(encoding='utf-8')Returns the string converted to bytes
str.maketrans(from, to, remove='')Builds a character-mapping table for use with translate()
s.translate(table)Applies a translation table, replacing or deleting characters

String Formatting — format(), format_map()

format() builds a string by filling in placeholders wrapped in {}. You can reference arguments by position, by keyword, or both.

PythonPython docs examples
# Positional — {0} refers to the first argument passed to format()
"The sum of 1 + 2 is {0}".format(1+2)
# 'The sum of 1 + 2 is 3'

# Keyword — {a}, {b}, {answer} match the keyword arguments by name
"The sum of {a} + {b} is {answer}".format(answer=1+2, a=1, b=2)
# 'The sum of 1 + 2 is 3'

# Positional args can be referenced out of order, or more than once
"{1} expects the {0} Inquisition!".format("Spanish", "Nobody")
# 'Nobody expects the Spanish Inquisition!'

format_map() — format from a dictionary directly

PythonPython docs example
class Default(dict):
    def __missing__(self, key):
        return key

'{name} was born in {country}'.format_map(Default(name='Guido'))
# 'Guido was born in country'  ← missing 'country' key falls back to the key name itself
format() vs f-strings: format() is the method form, and it's what the Python docs describe here — you'll see it in older code, string templates loaded from files, or anywhere the format string itself is a variable. For strings you're writing directly in your own code, an f-string like f"The sum is {1+2}" is the more common modern choice and does the same job with less punctuation.
MethodWhat it does
s.format(*args, **kwargs)Fills {} placeholders from positional and/or keyword arguments
s.format_map(mapping)Like format(**mapping), but uses the mapping directly — useful for dict subclasses with custom fallback behavior

Common Mistakes With These Methods

Expecting split() and rsplit() to differ without maxsplit

With no maxsplit argument, split() and rsplit() return identical results. The difference only shows up once maxsplit limits how many cuts happen.

Using split('\n') instead of splitlines() on real-world text

split('\n') misses \r-only line endings and leaves a trailing empty string after a final newline. splitlines() handles both correctly.

Passing non-string items to join()

", ".join([1, 2, 3]) raises TypeError: sequence item 0: expected str instance, int found. Convert each item with str() first, e.g. ", ".join(str(n) for n in nums).

Reaching for strip() when you mean removeprefix()/removesuffix()

strip() removes a set of characters; removeprefix()/removesuffix() remove one exact string. Mixing them up is the single most common gotcha carried over from Part 1.

Expecting center()/ljust()/rjust() to truncate

If the string is already longer than width, these methods return it completely unchanged — they only ever pad, they never cut a string down.

Passing an already-formatted string as the format() argument

"{0}".format(f"{name}") is redundant — if you're already using an f-string, you don't need .format() wrapped around it. Pick one approach per string.

Interview Questions and Answers

Q1 What's the difference between split() and rsplit()?
Without maxsplit, they behave identically. With maxsplit, split() counts splits from the left and rsplit() counts from the right — so '1,2,3'.rsplit(',', 1) gives ['1,2', '3'] while '1,2,3'.split(',', 1) gives ['1', '2,3'].
Q2 How is splitlines() different from split('\n')?
splitlines() recognizes several line-boundary characters beyond just \n — including \r and \r\n — and doesn't produce a trailing empty string for a final newline. split('\n') only splits on that one literal character and does leave the trailing empty string.
Q3 What do partition() and rpartition() return when the separator isn't found?
partition() returns a 3-tuple of (original string, '', ''). rpartition() returns the opposite arrangement: ('', '', original string). Both always return exactly three items, which makes them safe to unpack.
Q4 Why would you use removeprefix() instead of strip()?
strip() treats its argument as a set of characters and keeps removing any of them from the ends, which can eat more than intended. removeprefix() (and removesuffix()) remove one exact string, and only if it's actually present — nothing more, nothing less.
Q5 Why does join() sometimes raise a TypeError?
join() requires every item in the iterable to already be a string. Passing a list containing numbers, like [1, 2, 3], raises a TypeError because Python won't silently convert them — you need to call str() on each item first.
Q6 How do maketrans() and translate() work together?
maketrans() builds a lookup table mapping characters to their replacements (or to None to delete them). translate() then applies that table to a string in a single pass, which is more efficient than chaining multiple replace() calls for the same job.
Q7 What's the difference between format() and format_map()?
format(**mapping) copies the dictionary's contents into keyword arguments before filling the template. format_map(mapping) uses the mapping object directly without copying it — which matters if you're passing a custom dict subclass, like one that supplies a default value for missing keys via __missing__.

Mini Project — Build a Player Bio Formatter Using String Methods

Raw sign-up data is rarely ready to display as-is. This project takes a messy, single-line player record and turns it into a clean, aligned bio — using a method from nearly every section on this page.

Parse the raw record

Use split(',') to break a line like "mbappe,PSG,striker,24" into its individual fields.

Pull the label off a tagged field

If a field looks like "team: PSG", use partition(': ') to separate the label from the value in one step.

Clean up inconsistent text

Use replace() to fix known typos or old team names in the data, and removeprefix()/removesuffix() to strip labels like "Position: " that sometimes appear and sometimes don't.

Align the output into columns

Use ljust() for the name column and rjust() or zfill() for a numeric column like squad number, so every row of the printed roster lines up.

Assemble the final bio line

Use "{name} — {team}, {position}".format(...) (or an f-string) to build the final human-readable line from the cleaned-up fields.

Level up: read the raw records from a multi-line block of text with splitlines() instead of a single string, and join the finished bios back together for display with "\n".join(bios). It's the same round trip — split apart, clean, join back up — that most text-processing scripts end up doing.

FAQ

Without a maxsplit argument, they're identical. With maxsplit given, split() limits splits counting from the left, while rsplit() limits them counting from the right — so the leftover unsplit part ends up on opposite sides.
splitlines() recognizes multiple line-boundary characters (\n, \r, \r\n, and a few Unicode ones) and doesn't leave a trailing empty string for a final newline. split('\n') only ever splits on that one exact character.
A 3-tuple: the text before the separator, the separator itself, and the text after. partition() finds the first occurrence of the separator; rpartition() finds the last. If the separator isn't present, one of the outer two items becomes the whole original string and the rest are empty strings.
You call join() on the separator string, and pass it an iterable of strings to glue together: ", ".join(["a", "b", "c"]) gives "a, b, c". Every item in the iterable has to already be a string, or it raises a TypeError.
replace() swaps every occurrence of a substring anywhere in the string. removeprefix() and removesuffix() only remove the given text if it's exactly at the start or end, and only remove it once.
All three pad a string out to a fixed width. center() pads both sides, ljust() pads on the right (text stays left-aligned), and rjust() pads on the left (text stays right-aligned). None of them shorten a string that's already longer than the target width.
zfill() pads a string with leading zeros up to a given width, and it's aware of a leading + or - sign, keeping it in front of the zeros rather than after. It's commonly used for formatting IDs or numbers that need a fixed digit count, like "007".
maketrans() builds a character-mapping table — which characters should become which other characters, or be deleted entirely. translate() then applies that table across a string in a single pass, which is faster than chaining several replace() calls to do the same job.
format(**mapping) unpacks a dictionary into keyword arguments before substituting them into the template. format_map(mapping) uses the mapping object as-is without unpacking it, which is useful for a custom dict subclass that supplies fallback values for missing keys.
For strings you're writing directly in your code, an f-string is generally the simpler, more modern choice. format() is still useful when the template string itself comes from somewhere else — a config file, a translation string, or user input — since an f-string has to be written directly in your source code.
