Python Default Argument Values Explained (Python Docs 4.9.1) | Syntax, Evaluation Timing & The Mutable Default Trap

📖 Based on Python 3 official docs §4.9.1 — explained like a friend, with extra examples added
Python Beginner Functions Official Docs Updated July 2026

This page explains the official Python Default Argument Values documentation (Python Docs 4.9.1) in simple language. Default arguments let you call a function with fewer arguments than it technically accepts — but they come with a genuinely famous gotcha involving lists and dictionaries that catches almost every Python developer at least once.

By the end of this guide, you'll understand the classic ask_ok() example line by line, exactly when a default value gets evaluated, and why a function that "remembers" values across calls is very rarely what you actually wanted.

What Are Default Argument Values? (Python Docs 4.9.1 Explained)

A default argument value is a value Python automatically uses when the caller doesn't provide that argument. It lets a function have optional parameters, so callers only need to supply the information they want to change while everything else falls back to sensible defaults. Instead of forcing every caller to type out every single argument every single time, you give some parameters a sensible default — and callers only need to override it when they actually want something different.

Fewer required argumentsCallers can skip parameters that already have a sensible default
Set with =Written directly in the function signature: param=value
Evaluated onceAt definition time, not on every call — this matters a lot
Mutable defaults are riskyLists and dicts as defaults can quietly persist between calls

The ask_ok() Example

The Python docs introduce default arguments with a small interactive confirmation function — it asks a yes/no question, gives the user a limited number of retries, and repeats a reminder message if the answer isn't recognized:

PythonPython docs example
def ask_ok(prompt, retries=4, reminder='Please try again!'):
    while True:
        reply = input(prompt)
        if reply in {'y', 'ye', 'yes'}:
            return True
        if reply in {'n', 'no', 'nop', 'nope'}:
            return False
        retries = retries - 1
        if retries < 0:
            raise ValueError('invalid user response')
        print(reminder)

Two parameters here have defaults: retries defaults to 4, and reminder defaults to 'Please try again!'. Only prompt is mandatory — it has no default, so every call must supply it.

Calling ask_ok() in Several Ways

Because retries and reminder both have defaults, this one function can be called with one, two, or three arguments — and Python fills in whatever you leave out.

PythonPython docs example
# Giving only the mandatory argument — retries=4, reminder='Please try again!'
ask_ok('Do you really want to quit?')

# Giving one of the optional arguments — retries=2, reminder still default
ask_ok('OK to overwrite the file?', 2)

# Giving all arguments — nothing falls back to a default
ask_ok('OK to overwrite the file?', 2, 'Come on, only yes or no!')

The in Keyword — Testing Sequence Membership

The ask_ok() example also introduces the in keyword, used here to test whether the user's reply matches one of several accepted values without writing a long chain of or comparisons.

From the Python docs

This example also introduces the in keyword. This tests whether or not a sequence contains a certain value.

PythonKiddo example
reply = "yes"

# Without 'in' — verbose and repetitive
if reply == 'y' or reply == 'ye' or reply == 'yes':
    print("Confirmed")

# With 'in' — reads naturally and scales to any number of options
if reply in {'y', 'ye', 'yes'}:
    print("Confirmed")

When Are Default Values Evaluated?

Default values are evaluated exactly once — at the point the function is defined, in the scope where the def statement lives. They are not re-evaluated every time you call the function. This means a default tied to a variable captures whatever that variable's value was at definition time, even if the variable changes later.

From the Python docs

The default values are evaluated at the point of function definition in the defining scope.

PythonPython docs example
i = 5

def f(arg=i):
    print(arg)

i = 6
f()
# prints 5 — the default was locked in when f() was defined,
# NOT when f() was called
By the time f() is actually called, i has already changed to 6 — but it doesn't matter, because arg's default was fixed to 5 back when def f(arg=i): ran. The default is baked in at definition time, not looked up fresh on every call.

The Mutable Default Argument Trap

This is the single most famous gotcha in Python's default argument system. Because a default is evaluated only once, a mutable default — a list, a dict, or most class instances — is created once and then reused across every single call that relies on that default. Any changes made to it stick around for next time.

Important warning, straight from the docs: the default value is evaluated only once. This makes a real difference when the default is a mutable object such as a list or dictionary, since that same object gets reused on every call that doesn't override it.
PythonPython docs example
def f(a, L=[]):
    L.append(a)
    return L

print(f(1))
print(f(2))
print(f(3))

# [1]
# [1, 2]
# [1, 2, 3]
Imagine writing today's tasks in a notebook, then expecting a brand-new notebook tomorrow—but Python quietly hands you yesterday's notebook again. Mutable default arguments behave exactly like that: the same list or dictionary keeps getting reused unless you create a fresh one yourself.

Notice that L is never reset to an empty list between calls. The same list object created once, when f was defined, is being appended to on every call — which is almost never the behavior a beginner expects when they write L=[] in a function signature.

Kiddo extra — the same trap with a running total

PythonKiddo example
def add_note(note, notebook={}):
    notebook[len(notebook)] = note
    return notebook

print(add_note("Buy milk"))
print(add_note("Call Sarah"))

# {0: 'Buy milk'}
# {0: 'Buy milk', 1: 'Call Sarah'}
# The second call's "empty" notebook already had the first note in it!

The Fix — Default to None Instead

The standard workaround is to default the parameter to None — an immutable sentinel value — and create a fresh mutable object inside the function body every time it's actually needed.

PythonPython docs example
def f(a, L=None):
    if L is None:
        L = []
    L.append(a)
    return L

Now every call that doesn't pass its own L gets a brand-new empty list created fresh inside the function body — instead of sharing one list object across every call forever.

Kiddo extra — the fixed notebook function

PythonKiddo example
def add_note(note, notebook=None):
    if notebook is None:
        notebook = {}
    notebook[len(notebook)] = note
    return notebook

print(add_note("Buy milk"))
print(add_note("Call Sarah"))

# {0: 'Buy milk'}
# {0: 'Call Sarah'}
# Each call now gets its own fresh notebook, as expected
Rule of thumb: if a default value is a list, dict, set, or any other mutable object, default it to None and build the real value inside the function body instead. This one habit avoids the entire class of bug.

Common Default Argument Mistakes

Using a mutable object as a default value

def f(a, L=[]) shares the exact same list across every call that relies on the default. Default to None and create the list inside the function instead.

Expecting a variable-based default to update after definition

def f(arg=i) locks in whatever i was at definition time. Changing i afterward has no effect on future calls to f() — the default was already evaluated once and stored.

Putting a required argument after a default one

def f(a=1, b) raises a SyntaxError. Once a parameter has a default, every parameter after it must also have a default — required parameters always come first.

Forgetting that all optional parameters need their own default

If a function has three optional parameters, all three need a default value defined, even if you expect most calls to only override the first one.

Assuming this bug only affects lists

Dictionaries, sets, and instances of most custom classes are just as mutable as lists and fall into exactly the same trap. The fix — defaulting to None — applies to all of them.

Default Argument Interview Questions and Answers

Q1 What is a default argument value in Python?
A value assigned to a parameter in a function's definition, used automatically when the caller doesn't supply that argument. Written as def f(param=value):. It lets a function be called with fewer arguments than it's technically defined to accept.
Q2 When are default argument values evaluated?
Only once — at the point the function is defined, in the scope where the def statement runs. They are not re-evaluated on every call, which is why a default tied to a variable doesn't update even if that variable changes later.
Q3 Why is using a mutable default argument like L=[] considered dangerous?
Because the list is created exactly once at definition time and reused across every call that relies on the default. Any values appended in one call remain there for the next call, causing the function to accumulate state unexpectedly instead of starting fresh.
Q4 How do you fix the mutable default argument problem?
Default the parameter to None instead of the mutable object, then check if param is None: param = [] (or {}, etc.) inside the function body. This creates a brand-new object on every call that needs one.
Q5 Can you have a required parameter after an optional one in Python?
No. Once a parameter has a default value, every parameter that follows it must also have a default. Python raises a SyntaxError for a signature like def f(a=1, b):.
Q6 What does the in keyword do in the context of the ask_ok() example?
It checks whether a value exists inside a sequence or set — reply in {'y', 'ye', 'yes'} is True if reply matches any one of those three values, replacing a longer chain of or-joined equality checks.
