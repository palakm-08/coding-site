Python Lambda Expressions Explained (Python Docs 4.9.6) | Syntax, Closures & Sort Keys

Python Functions Intermediate Official Docs Updated July 2026

This page explains the official Python Lambda Expressions documentation (Python Docs 4.9.6) in simple language. A lambda is a small, anonymous function — no name, no def, just one expression — used in exactly the spots where writing a whole named function would feel like overkill.

What Is a Lambda Expression? (Python Docs 4.9.6 Explained)

A lambda expression is a small anonymous function created with the lambda keyword instead of def. It has no name of its own, and it can only contain a single expression — but that expression gets evaluated and returned automatically, without a return keyword.

From the Python docs

Small anonymous functions can be created with the lambda keyword. Lambda functions can be used wherever function objects are required. They are syntactically restricted to a single expression. Semantically, they are just syntactic sugar for a normal function definition.

AnonymousNo function name — created inline, right where it's needed
One expression onlyNo statements, no multiple lines — just a single expression
Implicit returnThe expression's result is automatically returned
Just sugar for defSemantically identical to a normal function definition

Basic Lambda Syntax

The docs' first example is about as simple as a lambda gets — a function that returns the sum of its two arguments:

lambda a, b : a+b ← the whole function, in one line
PythonPython docs example
lambda a, b: a+b

This is directly equivalent to writing a named function with def — just without giving it a name:

PythonKiddo example
# A lambda, assigned to a name for comparison
add = lambda a, b: a+b

# The equivalent def function
def add(a, b):
    return a + b

print(add(3, 4))
# 7

Restricted to a Single Expression

A lambda's body can only ever be one expression — no if blocks, no loops, no multiple statements, no assignments. This is a deliberate restriction: lambdas are meant for small, throwaway logic, not full function bodies.

PythonKiddo example
# A conditional expression IS allowed — it's still one expression
is_starting = lambda minutes: "starting" if minutes > 60 else "benched"
print(is_starting(75))
# starting

# A real if/else statement is NOT allowed inside a lambda — this is invalid:
# lambda minutes:
#     if minutes > 60:
#         return "starting"
# SyntaxError

The make_incrementor() Example — Lambdas and Closures

Like nested def functions, a lambda can reference variables from the scope it was created in. The docs demonstrate this with a function that builds and returns a customized lambda:

PythonPython docs example
def make_incrementor(n):
    return lambda x: x + n

f = make_incrementor(42)
f(0)
42
f(1)
43

Every time make_incrementor() runs, it returns a brand-new lambda that "remembers" the value of n from that specific call. f keeps that memory permanently — calling f(0) or f(1) always adds the same 42, no matter how many times you call f.

This is called a closure — the lambda "closes over" the variable n from its enclosing scope, carrying it along even after make_incrementor() has already finished running and returned.

Kiddo extra — a customized goal-bonus calculator

PythonKiddo example
def make_bonus_calculator(bonus_per_goal):
    return lambda goals: goals * bonus_per_goal

striker_bonus = make_bonus_calculator(50000)
winger_bonus = make_bonus_calculator(30000)

print(striker_bonus(20))   # 20 goals at 50000 each
print(winger_bonus(10))    # 10 goals at 30000 each
# 1000000
# 300000

Using lambda as a Sort Key

Beyond returning functions, a common use for lambdas is passing a small function as an argument to something else. list.sort() accepts a key function that decides what each item should be compared by — a lambda is perfect here, since you rarely need that comparison logic anywhere else.

PythonPython docs example
pairs = [(1, 'one'), (2, 'two'), (3, 'three'), (4, 'four')]
pairs.sort(key=lambda pair: pair[1])
pairs
[(4, 'four'), (1, 'one'), (3, 'three'), (2, 'two')]

The lambda lambda pair: pair[1] tells sort() to compare each tuple by its second element — the word — rather than the number. That's why the result ends up alphabetically sorted by word: four, one, three, two.

Kiddo extra — sorting a squad by goals scored

PythonKiddo example
squad = [("Haaland", 36), ("Foden", 19), ("Rodri", 4)]

# Sort by goals scored, highest first
squad.sort(key=lambda player: player[1], reverse=True)
print(squad)
# [('Haaland', 36), ('Foden', 19), ('Rodri', 4)]
Same pattern shows up everywhere: sorted(), max(), min(), and filter() all accept a key or condition function the same way sort() does — a lambda is almost always the natural fit when that function is only needed in this one spot.

lambda vs def — When to Use Which

Use lambda when
  • The logic is a single, simple expression
  • You need a quick function passed directly as an argument — like a sort key
  • You're generating a function from within another function, as in make_incrementor()
  • Giving it a name would add clutter without adding clarity
Use def when
  • The logic needs more than one expression or statement
  • You want a docstring explaining what the function does
  • The function will be reused in several places, so it deserves a name
  • Debugging matters — named functions show up clearly in tracebacks, lambdas just say <lambda>

Common Lambda Mistakes

Trying to fit a statement inside a lambda

Lambdas can only contain a single expression. Writing an if statement, a for loop, or an assignment inside one raises a SyntaxError — use a conditional expression, or switch to def.

Adding return inside a lambda

A lambda's expression is returned automatically — writing lambda x: return x + 1 is invalid syntax. Just write lambda x: x + 1.

Overusing lambda for anything with real logic

A lambda crammed with nested conditional expressions becomes genuinely hard to read. If it takes more than a few seconds to parse, it's a sign to write a named function with def instead.

Assigning a lambda to a variable just to name it

square = lambda x: x**2 works, but style guides generally recommend def square(x): return x**2 instead — if a lambda needs a name, it usually deserves to be a real function with a proper traceback name.

Forgetting a lambda still needs a colon

lambda a, b a+b without the colon between the parameters and the expression is a SyntaxError. The correct form is lambda a, b: a+b.

Lambda Interview Questions and Answers

Q1 What is a lambda expression in Python?
A small, anonymous function created with the lambda keyword instead of def. It's restricted to a single expression, which is evaluated and returned automatically — it's semantically just syntactic sugar for a normal function definition.
Q2 Can a lambda contain multiple statements?
No. A lambda's body must be exactly one expression — no loops, no multiple statements, no assignments. Conditional expressions are allowed since they're still a single expression, but full if statements are not.
Q3 What is a closure, and how does make_incrementor() demonstrate it?
A closure is a function that remembers variables from the scope it was created in, even after that outer scope has finished executing. make_incrementor(n) returns lambda x: x + n, and each returned lambda keeps its own captured value of n — calling make_incrementor(42) and make_incrementor(1) produces two independent functions.
Q4 Why would you use lambda with list.sort() instead of a regular function?
Because the sorting logic is usually only needed in that one call and doesn't deserve a permanent name elsewhere in the program. A lambda keeps the sort key inline and readable right where it's used, instead of scattering a tiny one-off function elsewhere in the file.
Q5 Is a lambda function faster than an equivalent def function?
No — there's no inherent performance difference. A lambda compiles to the same kind of function object as one defined with def; the only real difference is that a lambda has no name and is restricted to a single expression.
Q6 What does pairs.sort(key=lambda pair: pair[1]) actually do?
It sorts the list pairs in place, using the second element of each tuple as the comparison value instead of the whole tuple. Every item still stays in the list — only the ordering changes, based on whatever the lambda returns for each item.
