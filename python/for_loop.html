What is a for Statement? (Python Docs 4.2 Explained)

Python's for loop works differently from the for loop you might know from C or Pascal. Instead of stepping through a counter you define yourself, Python's for statement walks through the items of any sequence — a list, a string, a tuple — directly, in the order they appear. There's no manual index tracking, no separate halting condition to write. Python just hands you each item, one at a time.

This is one of the first things that feels genuinely different when moving from a language like C or Java into Python. You stop thinking "how do I count to the end of this array" and start thinking "give me each item in this collection."

Sequence-basedIterates directly over items, not over index numbers
No manual counterNo need to increment or check a halting condition yourself
Works on any iterableLists, strings, tuples, dicts, sets, files, and more
Preserves iteration orderItems are visited in the same order they appear in the iterable.
From the Python docs

Python's for statement iterates over the items of any sequence, in the order that they appear in the sequence, rather than always iterating over an arithmetic progression of numbers as in some other languages.

Basic for Loop Syntax

The Python docs illustrate this with a simple example — measuring the length of a few strings:

PythonPython docs example
# Measure some strings:
words = ['cat', 'window', 'defenestrate']
for w in words:
    print(w, len(w))

# cat 3
# window 6
# defenestrate 12

The pattern is always for <variable> in <iterable>:, followed by an indented block. On each pass, the loop variable is set to the next item, and the indented block runs once for that item.

Kiddo extra — looping over a list of players

PythonKiddo example
forwards = ["Mbappe", "Haaland", "Yamal"]

for player in forwards:
    print(f"{player} plays as a forward")

# Mbappe plays as a forward
# Haaland plays as a forward
# Yamal plays as a forward

Looping Over Different Sequences

Because Python's for loop works on any sequence, the same syntax applies whether you're looping over a list, a string, a tuple, or the keys of a dictionary.

PythonKiddo example
# Looping over a string — each character is one item
for letter in "Pedri":
    print(letter)
# P e d r i  (each on its own line)

# Looping over a tuple
midfielders = ("Bellingham", "Pedri", "Odegaard")
for name in midfielders:
    print(name)

# Looping over dictionary keys (default behaviour)
ratings = {"Mbappe": 91, "Haaland": 92}
for player in ratings:
    print(player, ratings[player])
# Mbappe 91
# Haaland 92
Looping directly over a dictionary gives you its keys, not its values. Use .items() if you want the key and value together — that's exactly what the next section on modifying collections uses.

The range() Function With for Loops

Sometimes you do need a counter — for example, to run a block a fixed number of times, or to access items by index. That's what range() is for. It generates a sequence of numbers on demand, without building the whole list in memory.

PythonKiddo example
# range(stop) — 0 up to (not including) stop
for i in range(5):
    print(i)
# 0 1 2 3 4

# range(start, stop)
for i in range(2, 6):
    print(i)
# 2 3 4 5

# range(start, stop, step)
for i in range(10, 0, -2):
    print(i)
# 10 8 6 4 2

# Access a list by index with range(len(...))
squad = ["Vinicius Jr", "Rodrygo", "Musiala"]
for i in range(len(squad)):
    print(i, squad[i])
# 0 Vinicius Jr
# 1 Rodrygo
# 2 Musiala
FormMeaningExample
range(stop)0 up to (not including) stoprange(5) → 0,1,2,3,4
range(start, stop)start up to (not including) stoprange(2,6) → 2,3,4,5
range(start, stop, step)start to stop, moving by steprange(10,0,-2) → 10,8,6,4,2
list(range(...))Materialize a range into a real listlist(range(3)) → [0,1,2]
Using an index when you only need the values is usually considered a code smell. If you find yourself writing for i in range(len(squad)): print(squad[i]) just to access each item, a simple for player in squad: is cleaner. Use enumerate() only when you actually need both the index and the value.

enumerate() — Index and Value Together

When you need both the position and the value while looping, enumerate() is the idiomatic way to get them — cleaner than manually tracking a counter or indexing with range(len(...)).

PythonKiddo example
squad = ["Foden", "Saka", "Bellingham"]

for index, name in enumerate(squad):
    print(index, name)
# 0 Foden
# 1 Saka
# 2 Bellingham

# Start counting from 1 instead of 0
for shirt_no, name in enumerate(squad, start=1):
    print(f"#{shirt_no} {name}")
# #1 Foden
# #2 Saka
# #3 Bellingham

Modifying a Collection While Iterating

This is where the Python docs give a genuinely important warning. Changing a collection while you're looping over that exact same collection can produce surprising, hard-to-predict results — items get skipped, or the loop behaves inconsistently.

From the Python docs

Code that modifies a collection while iterating over that same collection can be tricky to get right. Instead, it is usually more straightforward to loop over a copy of the collection or to create a new collection.

PythonPython docs example
# Create a sample collection
users = {'Hans': 'active', 'Éléonore': 'inactive', '景太郎': 'active'}

# Strategy: Iterate over a copy
for user, status in users.copy().items():
    if status == 'inactive':
        del users[user]

# Strategy: Create a new collection
active_users = {}
for user, status in users.items():
    if status == 'active':
        active_users[user] = status

Kiddo extra — the same two strategies, with a football squad

PythonKiddo example
squad_status = {"Mbappe": "fit", "Haaland": "injured", "Musiala": "fit"}

# Strategy 1 — iterate over a copy, edit the original safely
for player, status in squad_status.copy().items():
    if status == "injured":
        del squad_status[player]

print(squad_status)
# {'Mbappe': 'fit', 'Musiala': 'fit'}

# Strategy 2 — build a brand new collection instead
available = {}
for player, status in squad_status.items():
    if status == "fit":
        available[player] = status

print(available)
# {'Mbappe': 'fit', 'Musiala': 'fit'}
Why this matters: deleting from a dictionary or list while directly looping over it changes its size mid-iteration. Python's internal position tracking gets thrown off, and items can silently be skipped. Looping over .copy(), or building a fresh collection, sidesteps the problem entirely.

Nested for Loops

A for loop can contain another for loop inside it. The inner loop runs completely for every single pass of the outer loop — useful for grids, matchups, and any two-dimensional data.

PythonKiddo example
teams = ["Real Madrid", "Man City"]
stars = ["Mbappe", "Haaland"]

for team in teams:
    for star in stars:
        print(f"{team} vs a team with {star}")

# Real Madrid vs a team with Mbappe
# Real Madrid vs a team with Haaland
# Man City vs a team with Mbappe
# Man City vs a team with Haaland
The outer loop runs 2 times here, and the inner loop runs 2 times for each of those — 4 total print statements. Nested loops multiply: len(outer) × len(inner) iterations.

for...else in Python

Python lets a for loop have an else block. It's an unusual feature to languages outside Python — the else runs only if the loop finishes normally, without hitting a break.

PythonKiddo example
squad = ["Odegaard", "Saka", "Rice"]

for player in squad:
    if player == "Bellingham":
        print("Found him!")
        break
else:
    print("Bellingham is not in this squad")

# Bellingham is not in this squad
Think of it as a built-in "search finished without finding it" branch. If break runs, the else is skipped entirely. If the loop runs through every item without breaking, else executes.

break, continue & pass in for Loops

Three small keywords control the flow inside a loop body, and beginners often mix them up. break exits the loop entirely, continue skips to the next iteration, and pass does nothing at all — it's just a placeholder.

breakStops the loop immediately — no more iterations run
continueSkips the rest of this iteration, moves to the next item
passDoes nothing — a placeholder where code is syntactically required
PythonKiddo example
squad = ["Mbappe", "Haaland", "Yamal", "Musiala"]

# break — stop the loop entirely once a condition is met
for player in squad:
    if player == "Yamal":
        print("Found Yamal, stopping search")
        break
    print(f"Checking {player}...")
# Checking Mbappe...
# Checking Haaland...
# Found Yamal, stopping search

# continue — skip this iteration, keep looping
for player in squad:
    if player == "Haaland":
        continue   # skip Haaland, move to the next player
    print(player)
# Mbappe
# Yamal
# Musiala

# pass — a no-op placeholder, useful while sketching out logic
for player in squad:
    if player == "Musiala":
        pass   # TODO: handle Musiala's case later
    else:
        print(player)
# Mbappe
# Haaland
# Yamal
KeywordEffect on the loopWhen to reach for it
breakExits the loop immediately — remaining items are never visitedStop searching once you've found what you needed
continueSkips the rest of the current iteration, moves to the next itemSkip items that don't meet a condition without stopping the whole loop
passDoes nothing — the loop continues normally to the next linePlaceholder for a block you haven't written yet, or an intentionally empty branch
pass is not the same as continue. pass just fills a spot where Python's syntax requires a statement — it doesn't skip anything or affect the loop at all. continue actively jumps to the next iteration. Mixing these up is a common beginner mistake since both can appear to "do nothing visible" in simple examples.

Python for Loop vs while Loop

Use a for loop when
  • You already have a sequence — a list, string, tuple, or dict
  • You know how many times you want to loop, or the collection defines it
  • You need to process every item in a known collection
  • You want index + value together via enumerate()
Use a while loop when
  • The number of iterations isn't known ahead of time
  • You're waiting for a condition to change — user input, a flag, a timer
  • You need to keep looping until something specific happens
  • There's no ready-made sequence to iterate over
Featurefor loopwhile loop
Best forIterating over a known sequenceRepeating until a condition changes

Common Python for Loop Mistakes

Modifying a list or dict while looping over it directly

Deleting or adding items to the same collection you're iterating over can silently skip items. Loop over .copy() or build a new collection instead, as shown above.

Using range(len(...)) when a plain for loop would do

for i in range(len(squad)): print(squad[i]) works, but for player in squad: print(player) is simpler and more Pythonic — reach for range() or enumerate() only when you actually need the index.

Forgetting range(stop) doesn't include stop

range(5) gives 0, 1, 2, 3, 4 — five numbers, not including 5. A common off-by-one bug is expecting range(5) to include the number 5.

Confusing for...else with if...else

The else after a for loop doesn't mean "if the loop condition is false." It means "the loop finished without hitting break." These are unrelated to the else used with if.

Reusing the loop variable name after the loop ends

The loop variable still holds its last value after the loop finishes. Reusing that variable name elsewhere in the function without reassigning it can cause confusing bugs.

Python for Loop Interview Questions and Answers

These come up often in Python interviews — from beginner screens to backend engineering roles:

Q1 How is Python's for loop different from a C-style for loop?
A C-style for loop typically defines a counter, a condition, and an increment step manually. Python's for loop iterates directly over the items of a sequence — a list, string, tuple, or any iterable — without you managing an index or halting condition yourself.
Q2 Why shouldn't you modify a list or dict while looping over it?
Changing the size of a collection mid-iteration confuses the internal position tracking Python uses to step through it, which can cause items to be skipped or the loop to behave unpredictably. The safe approach is to loop over a copy (collection.copy()) or build a new collection instead.
Q3 What does range(5) actually produce?
It produces the numbers 0, 1, 2, 3, 4 — five values starting at 0, stopping before reaching 5. range() generates numbers lazily rather than building a full list in memory upfront.
Q4 What is the difference between range() and enumerate()?
range() generates a sequence of numbers, typically used as a counter. enumerate() wraps an existing iterable and yields (index, value) pairs together, so you get both the position and the item without indexing manually.
Q5 When does the else block of a for loop execute?
Only when the loop completes all its iterations without hitting a break statement. If break is triggered at any point, the else block is skipped entirely.
Q6 Can you loop over a dictionary directly? What do you get?
Yes — looping directly over a dictionary gives you its keys, not its values or key-value pairs. To get both key and value together, use .items(): for key, value in d.items():.
