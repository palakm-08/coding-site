Python break, continue & pass Explained (Python Docs 4.4 & 4.6) | Loop Control Statements

📖 Based on Python 3 official docs §4.4 & §4.6 — explained like a friend, with extra examples added
Python Beginner Control Flow Official Docs Updated August 2026

This page explains the official Python break, continue, and pass documentation (Python Docs §4.4 and §4.6) in simple language. Mixing these three up is one of the most common early Python mistakes, so this guide gives each one a clear, separate explanation.

By the end, you'll know exactly when a loop stops, when it just skips ahead, and when nothing happens at all — plus the classic factor-finding example straight from the Python docs.

What Are break, continue & pass? (Python Docs Explained)

break and continue are loop-control statements — they only make sense inside a for or while loop, and each changes what the loop does next. pass is different: it's a no-op statement that can be written anywhere Python's syntax requires a statement, loop or not — it just tells Python "nothing happens here."

breakExits the loop immediately — the rest of the iterable is never visited
continueSkips the rest of the current iteration, then re-checks the loop
passDoes absolutely nothing — a placeholder where Python requires a statement
break / continue onlyOnly valid inside a loop; pass works pretty much anywhere

The break Statement (Python Docs §4.4)

break exits the nearest enclosing loop immediately, no matter how many iterations were left. The Python docs demonstrate it with a classic example — finding the smallest factor of every number in a range:

From the Python docs

The break statement breaks out of the innermost enclosing for or while loop.

PythonPython docs example
for n in range(2, 10):
    for x in range(2, n):
        if n % x == 0:
            print(f"{n} equals {x} * {n//x}")
            break

4 equals 2 * 2
6 equals 2 * 3
8 equals 2 * 4
9 equals 3 * 3

As soon as a factor is found for a given n, break exits the inner loop — no need to keep checking larger values of x once the smallest factor is known. Notice 2, 3, 5, and 7 never print anything: they're prime, so the inner loop never finds a factor and runs to completion without hitting break.

Kiddo extra — stopping a search once you've found your player

PythonKiddo example
squad = ["Mbappe", "Bellingham", "Vinicius Jr", "Rodrygo"]

for player in squad:
    print(f"Checking {player}...")
    if player == "Vinicius Jr":
        print("Found him — stopping the search")
        break

# Checking Mbappe...
# Checking Bellingham...
# Checking Vinicius Jr...
# Found him — stopping the search
# Rodrygo is never checked — break exited the loop first
break only exits the innermost loop. In the nested docs example above, break stops the inner for x in range(2, n) loop only — the outer for n in range(2, 10) loop keeps going to its next value of n.

The continue Statement (Python Docs §4.4)

continue skips whatever's left in the current iteration and jumps straight back to the loop's next check — the loop keeps running, it just moves on early.

From the Python docs

The continue statement continues with the next iteration of the loop.

PythonPython docs example
for num in range(2, 10):
    if num % 2 == 0:
        print(f"Found an even number {num}")
        continue
    print(f"Found an odd number {num}")

Found an even number 2
Found an odd number 3
Found an even number 4
Found an odd number 5
Found an even number 6
Found an odd number 7
Found an even number 8
Found an odd number 9

Whenever num is even, the first print() runs and then continue jumps back to the top — the second print() is skipped for that pass. For odd numbers, continue never fires, so the code falls through to the second print() instead.

Kiddo extra — skipping injured players in a squad list

PythonKiddo example
squad_status = {"Haaland": "fit", "Foden": "injured", "Rodri": "fit"}

for player, status in squad_status.items():
    if status == "injured":
        continue   # skip injured players entirely
    print(f"{player} is available to start")

# Haaland is available to start
# Rodri is available to start

Output Prediction — Test Yourself

Before scrolling further, try to predict what this prints:

PythonPredict the output
for i in range(5):
    if i == 2:
        continue
    print(i)
Answer: 0, 1, 3, 4. When i reaches 2, continue fires before print(i) ever runs — so 2 is the only number missing. The loop doesn't stop; it just skips that one iteration and keeps going through 3 and 4.

Now a quick one with break:

PythonPredict the output
for i in range(5):
    if i == 2:
        break
    print(i)
Answer: 0, 1. This time the loop doesn't just skip 2 — it stops entirely the moment i == 2, so 3 and 4 never even get checked.

break and continue in Nested Loops

Both keywords only affect the innermost loop they're written inside — easy to overlook once loops start nesting.

Neither break nor continue can "reach" an outer loop. If you're two loops deep and call break, only the inner loop stops — the outer loop moves on to its next iteration exactly as if the inner loop had finished normally. There's no built-in way to break out of multiple loops at once; the usual workaround is a flag variable or moving the logic into a function and using return.

The pass Statement (Python Docs §4.6)

pass does nothing at all. It exists because Python's syntax requires a statement anywhere a block is opened — a completely empty while loop, function, or class would otherwise be a SyntaxError.

From the Python docs

The pass statement does nothing. It can be used when a statement is required syntactically but the program requires no action.

PythonPython docs example
while True:
    pass  # Busy-wait for keyboard interrupt (Ctrl+C)

pass shows up in a few recurring places — an empty class body, or a placeholder for logic you haven't written yet:

PythonPython docs example
# A commonly used minimal class — no attributes, no methods yet
class MyEmptyClass:
    pass

# A placeholder function while you're still sketching out the logic
def initlog(*args):
    pass   # Remember to implement this!
The Python docs' own note: for the placeholder-function case, many people write the ellipsis literal ... instead of pass. It has no special meaning to Python and isn't part of the language definition — but it's used conventionally as a placeholder body, just like pass.

Kiddo extra — pass as a deliberate "do nothing" branch

PythonKiddo example
squad = ["Saka", "Odegaard", "Rice"]

for player in squad:
    if player == "Odegaard":
        pass   # TODO: handle captain-specific logic later
    else:
        print(player)

# Saka
# Rice
# Odegaard is matched but nothing happens yet — pass is just marking the spot

When Should I Use Each?

  • Use break when you've found what you need and want to stop the loop right away — like ending a search the moment a match turns up.
  • Use continue when you want to skip the current item but keep looping — like ignoring injured players while still checking everyone else on the list.
  • Use pass when you intentionally want no action to happen yet, or need a placeholder so your code stays syntactically valid — like an unfinished function or a branch you haven't built out.

Common Mistakes With break, continue & pass

Confusing pass with continue

pass doesn't skip anything — it's a no-op that lets execution fall through. If the goal is to skip the rest of the current iteration, continue is the statement you actually want.

Expecting break to exit an outer loop

In nested loops, break only stops the innermost loop it's written inside. The outer loop keeps running its remaining iterations exactly as before.

Using break or continue outside a loop

Both only make sense inside a for or while loop. Writing either one anywhere else — like directly inside a function with no enclosing loop — raises a SyntaxError.

Putting code after continue in the same block, expecting it to run

Any code after continue in the same indentation block is unreachable for that iteration — continue jumps back to the loop check immediately.

Leaving a real pass in production code by accident

pass is meant as a temporary placeholder. Shipping a function that still just says pass silently does nothing when called — worth double-checking TODO placeholders before finishing a project.

break, continue & pass Interview Questions and Answers

Q1 What is the difference between break and continue?
break exits the loop entirely — no further iterations run. continue skips only the rest of the current iteration and moves on to the next one; the loop itself keeps running.
Q2 Does break exit all nested loops or just one?
Just one — the innermost loop that directly contains the break. Any outer loops continue running normally. There's no single keyword to break out of multiple nested loops at once.
Q3 What does the pass statement actually do?
Nothing. It's a placeholder Python requires wherever a statement is syntactically necessary but no action is needed — an empty class body, an unimplemented function, or a deliberately empty branch of an if statement.
Q4 Can you use break or continue outside a loop?
No — both raise a SyntaxError if used outside a for or while loop. They're only meaningful in the context of loop iteration.
Q5 What is commonly used instead of pass as a placeholder, and why?
The ellipsis literal .... It has no special meaning in the language and behaves identically to pass as a placeholder body, but many developers use it as a visual convention to mark "not yet implemented."
Q6 In the classic factor-finding example, why do prime numbers never print anything?
Because the inner loop only calls print() and break when it finds a factor (n % x == 0). For a prime number, that condition is never true for any x in the range, so the inner loop finishes all its iterations without ever printing or breaking.
