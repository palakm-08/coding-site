Python Keyword Arguments Explained (Python Docs 4.9.2) | kwarg=value Syntax, *args & **kwargs

📖 Based on Python 3 official docs §4.9.2 — explained like a friend, with extra examples added
Python Beginner Functions Official Docs Updated July 2026

This page explains the official Python Keyword Arguments documentation (Python Docs 4.9.2) in simple language. Keyword arguments let you call a function using name=value pairs instead of relying purely on position — which makes calls more readable and lets you skip arguments in any order you like, as long as you name them.

By the end of this guide, you'll understand the classic parrot() example line by line, exactly which calls are valid and which raise errors, and how *args and **kwargs let a function absorb an unlimited number of extra arguments through the cheeseshop() example.

What Are Keyword Arguments? (Python Docs 4.9.2 Explained)

A keyword argument is a way of calling a function using name=value instead of relying on position alone. Rather than remembering "the third argument is the action," you just write action='VOOOOOM' — the call reads like a sentence and can't be misread by argument order.

Named, not positionalWritten as kwarg=value — order in the call doesn't matter
Mixable with positional argsYou can use some positional arguments and some keyword arguments together
Self-documenting callsReading state='pushing up the daisies' tells you exactly what it sets
Strict matching rulesEvery keyword must match a real parameter name — no typos allowed

The parrot() Example

The Python docs introduce keyword arguments with a function that has one required argument and three optional ones:

PythonPython docs example
def parrot(voltage, state='a stiff', action='voom', type='Norwegian Blue'):
    print("-- This parrot wouldn't", action, end=' ')
    print("if you put", voltage, "volts through it.")
    print("-- Lovely plumage, the", type)
    print("-- It's", state, "!")

voltage is the one required argument — every call must supply it. state, action, and type all have defaults, so a caller only needs to override the ones they actually want to change.

Valid Ways to Call parrot()

Because keyword arguments can be named explicitly and don't have to appear in a fixed order, this one function can be called in quite a few different ways — all equally valid:

PythonPython docs example
parrot(1000)                                          # 1 positional argument
parrot(voltage=1000)                                  # 1 keyword argument
parrot(voltage=1000000, action='VOOOOOM')             # 2 keyword arguments
parrot(action='VOOOOOM', voltage=1000000)             # 2 keyword arguments
parrot('a million', 'bereft of life', 'jump')         # 3 positional arguments
parrot('a thousand', state='pushing up the daisies')  # 1 positional, 1 keyword
Notice the third and fourth calls: voltage=1000000, action='VOOOOOM' and action='VOOOOOM', voltage=1000000 give identical results even though the keywords are in a different order. That's the whole point of naming them — order stops mattering.

Invalid Calls

Not everything is allowed, though. These four calls each break a specific rule and raise an error:

PythonPython docs example
parrot()                     # required argument missing
parrot(voltage=5.0, 'dead')  # non-keyword argument after a keyword argument
parrot(110, voltage=220)     # duplicate value for the same argument
parrot(actor='John Cleese')  # unknown keyword argument

Keyword Arguments Must Follow Positional Arguments

In any single function call, every keyword argument must come after all the positional arguments. All the keywords you pass must match a real parameter name — order among the keyword arguments themselves doesn't matter, and this includes required parameters too.

From the Python docs

In a function call, keyword arguments must follow positional arguments. All the keyword arguments passed must match one of the arguments accepted by the function, and their order is not important. This also includes non-optional arguments — parrot(voltage=1000) is valid too.

No Argument May Receive a Value More Than Once

If a positional argument and a keyword argument both try to fill the same parameter, Python raises a TypeError immediately — the parameter would otherwise be getting two conflicting values.

PythonPython docs example
def function(a):
    pass

function(0, a=0)
Traceback (most recent call last):
  File "<stdin>", line 1, in <module>
TypeError: function() got multiple values for argument 'a'

Kiddo extra — the same clash with a Hollywood casting function

PythonKiddo example
def cast_lead(actor):
    print(f"Lead role goes to {actor}")

cast_lead("Tom Hanks", actor="Denzel Washington")
# TypeError: cast_lead() got multiple values for argument 'actor'
# "Tom Hanks" already filled the actor slot positionally —
# the keyword actor='Denzel Washington' collides with it

*args and **kwargs — Accepting an Arbitrary Number of Arguments

When a final formal parameter of the form **name is present, it collects every keyword argument that doesn't already match a named parameter, packaged up as a dictionary. This can be combined with *name, which collects any extra positional arguments as a tuple. *name must appear before **name in the parameter list.

From the Python docs

When a final formal parameter of the form **name is present, it receives a dictionary containing all keyword arguments except for those corresponding to a formal parameter. This may be combined with a formal parameter of the form *name, which receives a tuple containing the positional arguments beyond the formal parameter list. *name must occur before **name.

The cheeseshop() Example

The docs demonstrate *args and **kwargs together with the famous Cheese Shop sketch function — one required parameter, then an open-ended tuple of extra positional arguments, then an open-ended dictionary of extra keyword arguments:

PythonPython docs example
def cheeseshop(kind, *arguments, **keywords):
    print("-- Do you have any", kind, "?")
    print("-- I'm sorry, we're all out of", kind)
    for arg in arguments:
        print(arg)
    print("-" * 40)
    for kw in keywords:
        print(kw, ":", keywords[kw])

It could be called like this:

PythonPython docs example
cheeseshop("Limburger", "It's very runny, sir.",
           "It's really very, VERY runny, sir.",
           shopkeeper="Michael Palin",
           client="John Cleese",
           sketch="Cheese Shop Sketch")

and of course it would print:

Output
-- Do you have any Limburger ?
-- I'm sorry, we're all out of Limburger
It's very runny, sir.
It's really very, VERY runny, sir.
----------------------------------------
shopkeeper : Michael Palin
client : John Cleese
sketch : Cheese Shop Sketch
The order the keyword arguments are printed in is guaranteed to match the order they were passed in the function call — keywords preserves insertion order just like any other Python dictionary.

Kiddo extra — a movie booking function with *args and **kwargs

def book_premiere(movie, *costars, **crew):
    print(f"-- Booking the premiere for {movie}")
    for costar in costars:
        print(f"Also starring: {costar}")
    print("-" * 30)
    for role in crew:
        print(role, ":", crew[role])

book_premiere(

    "Leonardo DiCaprio",
    "Scarlett Johansson",

)

Common Keyword Argument Mistakes

Putting a positional argument after a keyword argument

parrot(voltage=5.0, 'dead') raises a SyntaxError. Once you use a keyword argument in a call, every argument after it must also be a keyword argument.

Passing the same parameter twice

function(0, a=0) raises TypeError: function() got multiple values for argument 'a' — the positional 0 already filled a, so the keyword a=0 conflicts with it.

Using a keyword that doesn't exist

parrot(actor='John Cleese') fails because actor isn't one of parrot's parameters. Python checks every keyword against the real parameter names — typos included.

Forgetting *args must come before **kwargs

In a function definition, *name (extra positional arguments) must appear before **name (extra keyword arguments) — writing them in the reverse order raises a SyntaxError.

Assuming **kwargs preserves no particular order

It actually does — since Python 3.7, dictionaries (including the one built by **kwargs) preserve insertion order, and the docs explicitly guarantee the printed order matches the order arguments were passed in the call.

Keyword Argument Interview Questions and Answers

Q1 What is a keyword argument in Python?
An argument passed to a function call in the form name=value, matched to a parameter by name instead of by position. It lets calls skip optional parameters and pass the ones they need in any order.
Q2 Can positional arguments come after keyword arguments in a function call?
No. Once a keyword argument appears in a call, every argument after it must also be a keyword argument. Positional arguments must always come first.
Q3 What happens if a parameter receives a value both positionally and by keyword?
Python raises a TypeError saying the function "got multiple values" for that argument. Each parameter may only be assigned a value once per call.
Q4 What does **kwargs do in a function definition?
It collects every keyword argument that doesn't match a named parameter into a dictionary, using the keyword names as dict keys. It must be the last parameter in the function's signature.
Q5 What is the difference between *args and **kwargs?
*args collects extra positional arguments into a tuple. **kwargs collects extra keyword arguments into a dictionary. Both let a function accept an arbitrary number of extra arguments, and *args must be defined before **kwargs in the parameter list.
Q6 Is the order of keyword arguments in a function call guaranteed when iterating over **kwargs?
Yes. The dictionary built from **kwargs preserves the order the keyword arguments were passed in the original call, so looping over it prints them back in that same order.
