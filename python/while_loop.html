What Is a while Loop in Python?

A while loop repeats a block of code for as long as a condition stays true. Unlike a for loop, which walks through a known sequence, a while loop doesn't know in advance how many times it will run — it just keeps checking its condition before every pass and stops the moment that condition turns false.

PythonBasic syntax
while condition:
    # code that runs while condition is True
    # something in here must eventually make condition False

Here's the smallest possible working example — a counter that stops itself:

PythonKiddo example
count = 1

while count <= 3:
    print(f"Count is {count}")
    count = count + 1

# Count is 1
# Count is 2
# Count is 3

count starts at 1, the condition checks whether it's still <= 3, and count = count + 1 at the end of the body is what eventually makes that condition false — that's what stops the loop.

Condition-drivenKeeps running as long as its condition evaluates to true
Checked up frontThe condition is tested before each pass, including the very first one
Unknown iteration countUnlike a for loop, it doesn't know ahead of time how many times it'll run
Needs its own progressSomething inside the loop must eventually make the condition false
Beginner tip: Every while loop should have a way to stop. If the condition never becomes false — or you forget to update the variable being checked — the loop will continue forever until you interrupt the program.

The Fibonacci Example — Python's First while Loop

The Python docs introduce while with a small program that prints the start of the Fibonacci sequence — each number is the sum of the two before it:

PythonPython docs example
# Fibonacci series:
# the sum of two elements defines the next
a, b = 0, 1
while a < 10:
    print(a)
    a, b = b, a+b

0
1
1
2
3
5
8

Every pass checks a < 10 before running the body. Once a reaches 13, the condition is false, and the loop stops — without ever printing 13.

Kiddo extra — counting down a match clock with while

PythonKiddo example
minutes_left = 5

while minutes_left > 0:
    print(f"{minutes_left} minutes left, still 0-0")
    minutes_left = minutes_left - 1

print("Full time!")
# 5 minutes left, still 0-0
# 4 minutes left, still 0-0
# 3 minutes left, still 0-0
# 2 minutes left, still 0-0
# 1 minutes left, still 0-0
# Full time!

Multiple Assignment and Evaluation Order

The Fibonacci example's first line, a, b = 0, 1, assigns both variables at once. The last line, a, b = b, a+b, reuses the same trick — and this is exactly what makes the classic swap-without-a-temp-variable pattern work.

From the Python docs

The first line contains a multiple assignment: the variables a and b simultaneously get the new values 0 and 1. On the last line this is used again, demonstrating that the expressions on the right-hand side are all evaluated first before any of the assignments take place. The right-hand side expressions are evaluated from left to right.

In a, b = b, a+b, Python first computes both b and a+b using the old values of a and b — only after both are calculated does it assign them to a and b. That ordering is exactly why this line correctly advances the Fibonacci sequence instead of corrupting it.

Truthy and Falsy Values in a while Condition

A while loop's condition doesn't have to be a plain comparison — Python is flexible about what counts as "true" here. Any non-zero number is true, zero is false. And it goes further: strings, lists, and any other sequence count too, based purely on whether they have any length at all.

From the Python docs

The while loop executes as long as the condition remains true. In Python, like in C, any non-zero integer value is true; zero is false. The condition may also be a string or list value, in fact any sequence; anything with a non-zero length is true, empty sequences are false.

PythonKiddo example
substitutes = ["Musiala", "Pedri", "Foden"]

# A non-empty list is truthy — the loop runs
while substitutes:
    player = substitutes.pop()
    print(f"{player} is coming on")

print("No substitutes left")
# Foden is coming on
# Pedri is coming on
# Musiala is coming on
# No substitutes left
# Once substitutes becomes [], it's falsy — the loop stops on its own

Indentation groups the loop body. The docs note that indentation is Python's way of grouping statements — every line inside the loop must be indented by the same amount, or Python raises an IndentationError.

print() and the end Keyword Argument

print() writes out its arguments, inserting a space between multiple items and printing strings without their quotes — which is exactly what makes it nicer for output than just writing a bare expression.

PythonPython docs example
i = 256*256
print('The value of i is', i)
The value of i is 65536

By default, print() ends its output with a newline. The end keyword argument lets you replace that newline with something else entirely — including nothing at all:

PythonPython docs example
a, b = 0, 1
while a < 1000:
    print(a, end=',')
    a, b = b, a+b

break and continue in while Loops

break exits the nearest enclosing while or for loop immediately. continue skips the rest of the current pass and jumps straight back to re-checking the loop's condition.

From the Python docs

The break statement breaks out of the innermost enclosing for or while loop. The continue statement continues with the next iteration of the loop.

The docs demonstrate both using for loops, but the exact same behavior applies inside a while loop. Here's the classic factor-finding example, rewritten with while:

PythonKiddo example
n = 2
while n < 10:
    x = 2
    while x < n:
        if n % x == 0:
            print(f"{n} equals {x} * {n//x}")
            break
        x = x + 1
    n = n + 1

4 equals 2 * 2
6 equals 2 * 3
8 equals 2 * 4
9 equals 3 * 3

Kiddo extra — continue with a while loop, skipping benched players

PythonKiddo example
squad = ["Haaland", "Foden", "Bench", "Rodri"]
i = 0

while i < len(squad):
    player = squad[i]
    i = i + 1
    if player == "Bench":
        continue
    print(f"{player} is starting")

# Haaland is starting
# Foden is starting
# Rodri is starting
Update your counter before continue. Notice i = i + 1 runs before the continue check above. In a while loop, forgetting to update your loop variable before a continue creates an infinite loop — for loops don't have this risk since the next item is handled automatically.

The while...else Clause

A while loop can have an else clause, just like a for loop. It runs once the loop's condition becomes false naturally — but is skipped entirely if the loop exits early via break (or a return, or a raised exception).

From the Python docs

In a while loop, the else clause is executed after the loop's condition becomes false. In either kind of loop, the else clause is not executed if the loop was terminated by a break. Other ways of ending the loop early, such as a return or a raised exception, will also skip execution of the else clause.

The docs demonstrate this pattern with a prime-number search using for; here's the same idea rewritten with while:

PythonKiddo example
n = 2
while n < 10:
    x = 2
    while x < n:
        if n % x == 0:
            print(n, 'equals', x, '*', n//x)
            break
        x = x + 1
    else:
        # loop fell through without finding a factor
        print(n, 'is a prime number')
    n = n + 1

2 is a prime number
3 is a prime number
4 equals 2 * 2
5 is a prime number
6 equals 2 * 3
7 is a prime number
8 equals 2 * 4
9 equals 3 * 3
One way to think about it: imagine the else paired with the if inside the loop, running a sequence like if/if/if/else. Each time the inner if fires, a break happens. If the condition is never true across the whole loop, the else outside the loop finally runs.

The pass Statement

pass does nothing at all. It exists because Python requires a statement anywhere a block is opened — a completely empty while body, function, or class would otherwise be a syntax error.

From the Python docs

The pass statement does nothing. It can be used when a statement is required syntactically but the program requires no action.

PythonPython docs example
while True:
    pass  # Busy-wait for keyboard interrupt (Ctrl+C)

pass also shows up outside loops — as a minimal class body, or a placeholder for a function you haven't implemented yet:

PythonPython docs example
class MyEmptyClass:
    pass

def initlog(*args):
    pass   # Remember to implement this!
For the placeholder-function case, many people write the ellipsis literal ... instead of pass. It has no special meaning to Python and isn't part of the language definition — but it's used conventionally as a placeholder body just the same.

Common while Loop Mistakes

Forgetting to update the loop variable

If nothing inside the loop body changes the value being tested, the condition never becomes false and the loop runs forever. Every while loop needs something that moves it toward its exit condition.

Updating the counter after a continue

If continue runs before the line that updates your loop variable, that update gets skipped every time the condition is met — creating an infinite loop. Update the counter before any continue check.

Expecting while...else to run like an if...else

The else on a while loop runs when the loop's condition becomes false naturally — not simply "if the condition was ever false." A break anywhere in the loop skips the else entirely.

Inconsistent indentation inside the loop body

Every line inside a while loop must be indented by the same amount. Mixing tabs and spaces, or indenting inconsistently, raises an IndentationError before the loop even runs.

Assuming pass skips to the next iteration

pass does nothing — it doesn't skip anything. If the goal was to skip the rest of the current iteration, continue is the correct statement, not pass.

While Loop Interview Questions and Answers

Q1 What is the difference between a while loop and a for loop?
A for loop iterates over a known sequence, running once per item. A while loop repeats based on a condition and doesn't know in advance how many times it will run — it keeps going until that condition becomes false.
Q2 What values does Python consider falsy in a while condition?
Zero, empty sequences (empty strings, lists, tuples), and None are all falsy. Any non-zero number and any sequence with at least one element are truthy.
Q3 When does the else clause of a while loop execute?
After the loop's condition becomes false naturally, without ever hitting a break. If break runs at any point, the else block is skipped entirely.
Q4 How do you create an infinite loop on purpose in Python, and why would you?
while True: creates a loop that never stops on its own condition. It's useful for things like a busy-wait for a keyboard interrupt, or a server loop that should keep running until explicitly told to stop with a break.
Q5 What is the difference between pass and continue inside a while loop?
pass does nothing — code after it in the same iteration still runs. continue actively skips the rest of the current iteration and jumps back to re-check the loop's condition.
Q6 Why must every line in a while loop's body be indented by the same amount?
Python uses indentation, not braces, to define where a block starts and ends. Inconsistent indentation makes it impossible for Python to tell which lines belong to the loop body, resulting in an IndentationError.
