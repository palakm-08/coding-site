Python match Statement Explained (Python Docs 4.7) | Pattern Matching, case Blocks & Class Patterns

📖 Based on Python 3 official docs §4.7 — explained like a friend, with extra examples added
Python Beginner Control Flow Official Docs Updated August 2026

This page explains the official Python match statement documentation (Python Docs §4.7) in simple language. A match statement compares a value against a series of patterns and runs whichever case block matches first — it looks a little like a switch statement from other languages, but it can do a lot more: it can peek inside tuples, class instances, lists, and dictionaries, and pull values straight out of them into variables.

By the end of this guide, you'll understand literal patterns, capturing values, matching class instances, guards, and the sequence/mapping patterns — plus the classic Point examples straight from the Python docs.

What is a match Statement? (Python Docs 4.7 Explained)

A match statement takes a subject value and compares it against a series of case patterns, top to bottom. The first pattern that matches runs — and unlike a plain equality check, a pattern can also unpack the value and bind pieces of it to new variables at the same time.

From the Python docs

A match statement takes an expression and compares its value to successive patterns given as one or more case blocks. This is superficially similar to a switch statement in C, Java or JavaScript, but it's more similar to pattern matching in languages like Rust or Haskell. Only the first pattern that matches gets executed, and it can also extract components from the value into variables. If no case matches, none of the branches is executed.

First match winsPatterns are checked top to bottom — only the first successful one runs
Can destructureA pattern can pull values out of tuples, objects, lists, and dicts
No match = no-opIf nothing matches and there's no wildcard, none of the branches run
_ is the wildcardThe underscore pattern matches anything and never fails

Basic Literal Patterns

The simplest form of match just compares the subject against one or more literal values — numbers, strings, or constants.

PythonPython docs example
def http_error(status):
    match status:
        case 400:
            return "Bad request"
        case 404:
            return "Not found"
        case 418:
            return "I'm a teapot"
        case _:
            return "Something's wrong with the internet"
The final case _: is the wildcard — from the Python docs, the "variable name" _ acts as a wildcard and never fails to match. It's the closest thing match has to a default or final else branch.

Kiddo extra — matching an alter ego to a hero name

PythonKiddo example
def secret_identity(name):
    match name:
        case "Peter":
            return "Spider-Man"
        case "Harry":
            return "New Goblin"
        case _:
            return "Just a regular civilian"

print(secret_identity("Peter"))
# Spider-Man

Combining Several Literals with |

Use | ("or") to match any one of several literals in a single case, instead of repeating the same result across multiple blocks.

PythonPython docs example
case 401 | 403 | 404:
    return "Not allowed"

Kiddo extra — grouping allies together

PythonKiddo example
match name:
    case "Harry" | "MJ" | "Norah":
        print("A trusted ally")
    case _:
        print("Unknown to Peter")

Capturing Values from Patterns

Patterns can look like unpacking assignments and bind pieces of the subject to variables. This is what genuinely sets match apart from a simple if/elif chain — a pattern can both check and extract in one step.

PythonPython docs example
# point is an (x, y) tuple
match point:
    case (0, 0):
        print("Origin")
    case (0, y):
        print(f"Y={y}")
    case (x, 0):
        print(f"X={x}")
    case (x, y):
        print(f"X={x}, Y={y}")
    case _:
        raise ValueError("Not a point")
From the Python docs

Study that one carefully! The first pattern has two literals, and can be thought of as an extension of the literal pattern shown above. The next two patterns combine a literal and a variable, and the variable binds a value from the subject. The fourth pattern captures two values, conceptually similar to the unpacking assignment (x, y) = point.

Kiddo extra — reading a (name, power level) pair

PythonKiddo example
hero = ("Peter", 0)

match hero:
    case ("Peter", 100):
        print("Peak Spider-Man")
    case (name, 0):
        print(f"{name} has no powers right now")
    case (name, level):
        print(f"{name} at power level {level}")

# Peter has no powers right now

Matching Class Instances

If your data is structured as objects rather than tuples, match can use the class name like a constructor call and capture attributes straight into variables.

PythonPython docs example
class Point:
    def __init__(self, x, y):
        self.x = x
        self.y = y

def where_is(point):
    match point:
        case Point(x=0, y=0):
            print("Origin")
        case Point(x=0, y=y):
            print(f"Y={y}")
        case Point(x=x, y=0):
            print(f"X={x}")
        case Point():
            print("Somewhere else")
        case _:
            print("Not a point")
A recommended way to read patterns, per the Python docs: look at them as an extended form of what you'd put on the left of an assignment, to see which variables get set to what. Only standalone names (like y above) are actually assigned — the keyword names (x=, y=) and the class name (Point) are never assigned to.

Kiddo extra — matching a SpiderPerson object

PythonKiddo example
class SpiderPerson:
    def __init__(self, name, universe):
        self.name = name
        self.universe = universe

def which_spiderverse(hero):
    match hero:
        case SpiderPerson(name="Peter", universe=616):
            print("Earth-616 Peter Parker")
        case SpiderPerson(universe=616):
            print("Someone else from Earth-616")
        case SpiderPerson():
            print("A Spider-Person from another universe")
        case _:
            print("Not a Spider-Person at all")

__match_args__ & Positional Patterns

Matching everything by keyword (x=, y=) works, but it's a little verbose. Setting __match_args__ on a class lets you match those same attributes positionally instead.

From the Python docs

You can use positional parameters with some builtin classes that provide an ordering for their attributes (e.g. dataclasses). You can also define a specific position for attributes in patterns by setting the __match_args__ special attribute in your classes. If it's set to ("x", "y"), the following patterns are all equivalent (and all bind the y attribute to the var variable): Point(1, var), Point(1, y=var), Point(x=1, y=var), Point(y=var, x=1).

Kiddo extra — positional matching on SpiderPerson

PythonKiddo example
class SpiderPerson:
    __match_args__ = ('name', 'universe')
    def __init__(self, name, universe):
        self.name = name
        self.universe = universe

# These four patterns are all equivalent, thanks to __match_args__:
#   SpiderPerson("Peter", world)
#   SpiderPerson("Peter", universe=world)
#   SpiderPerson(name="Peter", universe=world)
#   SpiderPerson(universe=world, name="Peter")

Guards — Adding an if to a Pattern

A guard is an extra if condition tacked onto a pattern. If the pattern matches but the guard is false, match moves on and tries the next case block instead.

PythonPython docs example
match point:
    case Point(x, y) if x == y:
        print(f"Y=X at {x}")
    case Point(x, y):
        print("Not on the diagonal")
Value capture happens before the guard is checked. In the example above, x and y are bound from point first, and only then does Python evaluate x == y. If the guard fails, those bindings are discarded and the next case is tried from scratch.

Kiddo extra — a guard on universe number

PythonKiddo example
match hero:
    case SpiderPerson(name, universe) if universe > 1000:
        print(f"{name} is from a far-future universe")
    case SpiderPerson(name, universe):
        print(f"{name} is from universe {universe}")

Nested Patterns

Patterns can nest arbitrarily deep — a list pattern can contain class patterns, which can contain their own nested patterns, and so on.

PythonPython docs example
class Point:
    __match_args__ = ('x', 'y')
    def __init__(self, x, y):
        self.x = x
        self.y = y

match points:
    case []:
        print("No points")
    case [Point(0, 0)]:
        print("The origin")
    case [Point(x, y)]:
        print(f"Single point {x}, {y}")
    case [Point(0, y1), Point(0, y2)]:
        print(f"Two on the Y axis at {y1}, {y2}")
    case _:
        print("Something else")
Subpatterns can also be captured whole using as — from the Python docs, case (Point(x1, y1), Point(x2, y2) as p2): captures the second element of the input as p2, as long as the input is a sequence of exactly two points.

Sequence, Mapping & Other Pattern Features

A handful of extra rules round out how patterns work with sequences, dictionaries, and named constants.

FeatureWhat it doesExample
Sequence patternsMatch any sequence (but not strings or iterators) using tuple/list syntaxcase [x, y]:
Extended unpackingCapture "the rest" of a sequence, just like unpacking assignmentscase [x, y, *rest]:
Mapping patternsCapture specific keys from a dict — extra keys are ignoredcase {"name": n, "universe": u}:
Dict rest captureCapture remaining key/value pairs (**_ isn't allowed — it'd be redundant)case {"name": n, **rest}:
Capture with asBind a whole matched subpattern to a namecase Point() as p:
Singleton identityTrue, False, and None are compared by identity, not equalitycase None:
Named constantsUse a dotted name so it's treated as a constant, not a new capture variablecase Color.RED:
PythonPython docs example
from enum import Enum
class Color(Enum):
    RED = 'red'
    GREEN = 'green'
    BLUE = 'blue'

color = Color(input("Enter your choice of 'red', 'blue' or 'green': "))

match color:
    case Color.RED:
        print("I see red!")
    case Color.GREEN:
        print("Grass is green")
    case Color.BLUE:
        print("I'm feeling the blues :(")
Dotted names matter here. The Python docs are explicit that named constants must be written as dotted names (like Color.RED) to prevent them from being interpreted as new capture variables. Writing case RED: without the dot would instead create a variable named RED that matches anything — not what you want.

Common match Statement Mistakes

Forgetting the wildcard case

Without a final case _:, if nothing matches, none of the branches run at all — silently. Always add a wildcard when you need a guaranteed fallback.

Writing a named constant without a dot

case RED: (no dot) creates a brand-new capture variable named RED that matches anything — it does not compare against an existing constant. Use a dotted name like case Color.RED: instead.

Expecting a sequence pattern to match a string

Tuple and list patterns match arbitrary sequences, but the Python docs explicitly carve out an exception: they don't match iterators or strings, even though a string is technically iterable.

Putting a broad pattern before a specific one

match checks patterns top to bottom and stops at the first match. A general pattern like Point() placed above a more specific one like Point(x=0, y=0) will catch everything first, and the specific case never runs.

Using **_ in a mapping pattern

Capturing the "rest" of a dict with **rest is fine, but **_ specifically is disallowed — since you're discarding it anyway, it would be redundant and Python doesn't permit it.

match Statement Interview Questions and Answers

Q1 How is Python's match statement different from a switch statement in other languages?
A switch statement typically only compares a value against literal constants. Python's match can do structural pattern matching — it can destructure tuples, class instances, lists, and dicts, binding pieces of the matched value into new variables at the same time it checks the pattern.
Q2 What does the underscore (_) mean in a case pattern?
It's a wildcard pattern that matches anything and never fails. It's commonly used as the final case _: to provide a fallback, similar to a default branch in a switch statement.
Q3 What is a guard clause in a match statement?
An extra if condition attached to a case pattern. Value capture happens first — if the pattern matches structurally but the guard evaluates to False, match moves on to try the next case block instead of running this one.
Q4 What does __match_args__ do?
It's a special class attribute that defines which attributes can be matched positionally instead of by keyword. Setting __match_args__ = ("x", "y") lets you write Point(1, 2) instead of always having to write Point(x=1, y=2).
Q5 Why must named constants in patterns use dotted names?
A bare name in a pattern (like RED) is treated as a new capture variable that matches anything, not a comparison against an existing value. Writing it as a dotted name (like Color.RED) tells Python to treat it as a named constant to compare against, instead of creating a variable.
Q6 Do sequence patterns match strings?
No. Even though a string is technically an iterable sequence of characters, the Python docs specifically exclude strings (and iterators in general) from matching tuple and list patterns — they only match arbitrary sequences like lists and tuples.
